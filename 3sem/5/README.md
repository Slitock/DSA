# Практическая работа №5: Алгоритмы поиска по ключу

Проект реализует алгоритмы поиска в неупорядоченных бинарных файлах, состоящих из записей фиксированного размера. Предметная область по варианту №21 — «Справочная межгорода» (уникальный ключ: `код города`, данные: `название города`).

## Архитектура проекта

**1. Директория `Head_Files/` (Заголовочные файлы)**

* `generator.h` — содержит структуру `CityRecord` (формат записи для бинарного файла) и объявление функции генерации.
* `linear_search.h` — содержит объявление функции для прямого линейного поиска по файлу.
* `fibonacci_search.h` — содержит структуру `IndexRecord` (для хранения пары «ключ-смещение» в оперативной памяти) и объявления функций для создания таблицы индексов, её сортировки, поиска Фибоначчи и чтения записи по прямому смещению.

**2. Директория `Source_Files/` (Исходный код)**

* `generator.cpp` — генерирует заданное число уникальных ключей и формирует бинарный файл. Данные записываются цельными блоками через приведение типов к `char*`.
* `linear_search.cpp` — реализация метода грубой силы (Задание 1). Последовательно считывает структуры из файла до тех пор, пока не встретит искомый ключ или не достигнет конца файла.


* `fibonacci_search.cpp` — реализация оптимизированного поиска (Задание 2). Файл читается один раз для извлечения только ключей и адресов байтов (смещений), которые сохраняются в массив `std::vector<IndexRecord>`. После сортировки массива применяется поиск Фибоначчи. Вычисленное смещение используется для мгновенного доступа к нужной записи в файле через функцию `seekg`.


* `main.cpp` — тестирующий модуль. Автоматически прогоняет оба алгоритма на объемах в 100, 1000 и 10 000 элементов. Имитирует худший сценарий, принудительно запрашивая поиск последнего ключа в файле, и выводит результаты времени $T(n)$ и числа сравнений $T_ф$ в виде таблицы.



**3. Директория `bin/` (Данные)**

* Папка для хранения сгенерированных файлов `cities_100.bin`, `cities_1000.bin`, `cities_10000.bin`. Добавлена в `.gitignore`, чтобы тяжелые бинарники не попадали в репозиторий.

## Сборка и запуск

Для компиляции проекта используется `g++`. Находясь в директории `Source_Files`, необходимо выполнить:

```bash
# Флаг -I указывает компилятору путь к заголовочным файлам
g++ main.cpp generator.cpp linear_search.cpp fibonacci_search.cpp -I ../Head_Files -o pr
./pr

```

## Вычислительная сложность алгоритмов

* **Линейный поиск:** Асимптотическая сложность $O(n)$. Для поиска элемента в худшем случае алгоритм вынужден загрузить с диска и проверить каждую запись.
* **Поиск Фибоначчи (с таблицей смещений):** Сложность самого поиска в оперативной памяти составляет $O(\log n)$. Алгоритм делит массив индексами, равными числам Фибоначчи, используя только операции сложения и вычитания. Доступ к итоговой записи в файле выполняется за $O(1)$.
